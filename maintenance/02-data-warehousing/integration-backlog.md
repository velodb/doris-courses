# Level 1 尚未交付的实验

这些内容属于已规划的 Level 1，不因首版未实现而从课程目标中删除。
没有通过实验的路径不得进入录制稿的“成功结果”。

| 单元 | 尚缺什么 | 补齐后如何验收 |
|---|---|---|
| D02 | 放大数据、Query Profile、受控 Rowset 观察和持续写入对照 | 相同数据结果，扫描/版本与批次证据可解释；记录机器与配置，不固定性能倍数 |
| D03 | 放大数据上的物理设计对照 | 计划与运行时扫描证据结合，不只看两个订单的耗时 |
| D04 | Iceberg 服务与数据初始化、Catalog 创建和文件 TVF 实验 | 使用 WWI 十单投影的实际湖表，对照十行 12220.60；现有候选 Notebook 需要预置 Catalog |
| D05-03 | 默认值、生成列与更多导入转换演示 | 固定省略字段的预期行为，并验证目标版本限制 |
| D05-04 | Group Commit sync/async 行为 | 分别观测响应与可见时间，核对结果；不复用 off_mode 的 label 结论 |
| D05-05 | Broker Load 与 S3 TVF + INSERT SELECT | 独立目标表与同一基线对账，核对异步任务最终状态 |
| D05-06 | Kafka/Routine Load 环境和九次模拟事件投递 | 记录位点、暂停/恢复、完整性及业务版本；不将消费进度当最新状态 |
| D05-07 | MySQL/Flink CDC/Connector 兼容环境 | 快照与增量、增删改、任务中断与恢复，对照源库与目标 |
| D05-08 | Doris 4.1 CDC_STREAM 目标补丁验证 | 明确模式、源表要求、位点和恢复，不猜测语法 |
| D05-09 | Streaming Job 对象存储持续文件实验 | 文件发现、处理进度、迟到与补数按目标版本实测 |
| D09-A | Schema Change、更多脏数据与动态新鲜度 | 扩展数据契约与独立预期，验证下游兼容性和真实接入延迟 |
| D06 | 导入删除标记、真实 CDC 位点恢复和事件 ID 冲突 | 独立删除样本；源端恢复后当前状态与历史逐行对账；冲突不能静默覆盖 |

制作方式：逐路径加入本 Level 1 分支的后续提交，或拆为依赖首版的小 PR。
先固定输入、预期和版本，再写演示，最后录制。不要把候选 Notebook、
离线测试通过或单节点开发构建成功等同于全部课程验收。
