# Apache Doris көмегімен нақты уақыттағы аналитика

Интернет-саудадағы он миллион оқиғадан тұратын бір деректер жиынымен Apache Doris негізінде нақты уақыттағы аналитика жүйесін құрып, іске қосыңыз. Doris сынақ ортасын ашып, оқиғаларды жүктейсіз, Doris оларды қалай жоспарлайтынын, сақтайтынын және сканерлейтінін көресіз. Деректерді өндірістік жүйелердегідей файлдан, S3-тен және Kafka-дан жүктейсіз. Кейін оқиғаларды егжей-тегжейлі және жиынтық кестелерге модельдеп, функциялармен, терезелік функциялармен және біріктірулермен талдайсыз; жаңарту мен жою арқылы тапсырыстардың ағымдағы күйін дұрыс сақтайсыз. Соңында жауаптарды өзгертпей сұрауларды жеделдетесіз, үш FE және үш BE бар кластерді ақаулар жағдайында сынайсыз және деректердің өмірлік циклін тексерілген қалпына келтіру жолымен басқарасыз. Әр зертханалық жұмыс өз компьютеріңізде, курс іске қосатын Doris сынақ ортасында орындалады және нәтижелерді тексере алатын сандармен салыстырады.

<a id="who-this-course-is-for"></a>

## Курс кімге арналған?

- Doris негізінде нақты уақыттағы бақылау тақталарын немесе талдамалық қызметтерді құратын не құруды жоспарлайтын деректер инженерлеріне, аналитика инженерлеріне және бэкенд әзірлеушілеріне.
- `SELECT`, `WHERE`, `GROUP BY` және `JOIN` бар SQL жаза білуіңіз; қысқа Python ұяшығын оқып, ондағы мәнді өзгерте алуыңыз; `docker ps` және `docker logs` сияқты негізгі Docker командаларын орындай білуіңіз керек. 3-модуль HTTP сұрауларын `curl` арқылы жібереді, ал 9-модуль контейнерлерді тоқтатып, іске қосады; әр зертханалық жұмыста командалар көрсетілген.
- Doris тәжірибесі қажет емес. 1-модуль сынақ ортасын іске қосып, алғашқы кестеңізді құруға көмектеседі.

## Не үйренесіз?

- Doris қалай жұмыс істейді: FE сұрауды жоспарлайды, BE түйіндері оны орындайды; бағандық сақтау мен векторланған орындау; сұраудың қанша дерек оқитынын анықтайтын Partition, Tablet, Rowset және Segment құрылымдары.
- Деректерді қалай жүктеп, дұрыстығына көз жеткізуге болады: Stream Load, `INSERT INTO SELECT` бар S3 кестелік функциясы, Kafka-дан Routine Load және Group Commit; әрқайсысының аяқталуын дәлелдейтін нәтиже мен қауіпсіз қайталау жолы.
- Қалай модельдеп, талдау керек: деректің түйіршіктілігі, кесте модельдері, типтер мен орналасу; функциялар, CTE және терезелік функциялар; жолдарды жоғалтпайтын да, көбейтпейтін де біріктірулер; ағымдағы күйге арналған жаңарту, ішінара жаңарту, `MERGE INTO` және жою.
- Сұрауларды жылдамдатып, дұрыстығын сақтау: көріністер, материалданған көріністер, индекстер мен статистика; `EXPLAIN` және Query Profile арқылы тексеру.
- Doris жүйесін пайдалану: репликалар, FE ақауынан ауысу, көпшілік түйін растаған жазу және біріктіру кезінде BE түйіндері арасындағы деректер қозғалысы; сығу, жылжымалы уақыт терезелері және қате жоюдан кейін қалпына келтіру.

<a id="ports-and-docker-objects"></a>

### Порттар және Docker нысандары

Курстың әр Docker ресурсы `doris-rta` префиксінен басталады, ал әр хост порты `127.0.0.1` мекенжайына байланған. Сондықтан курс осы репозиторийдің басқа курстарымен қатар жұмыс істей алады. Басқа хост портын қолдану үшін оның айнымалысын Jupyter іске қосылмай тұрып орнатып, Jupyter ортасын әр жолы бірдей мәндермен іске қосыңыз: ноутбуктер, олардың shell ұяшықтары мен Compose файлдары бірдей айнымалыларды оқиды.

| Не үшін? | Docker нысандары | Хост порттары (айнымалылар) |
| --- | --- | --- |
| Бір түйінді сынақ ортасы, 1–8 және 10-модульдер | `doris-rta` контейнері, `doris-rta` желісі, `doris-rta-fe-meta` және `doris-rta-be-storage` томдары | FE сұрауы 19030 (`DORIS_RTA_QUERY_PORT`), FE HTTP 18030 (`DORIS_RTA_HTTP_PORT`), BE HTTP 18040 (`DORIS_RTA_BE_HTTP_PORT`) |
| Kafka брокері, 3-модуль | `doris-rta-kafka` Compose жобасы, `doris-rta-kafka` контейнері | 19092 (`DORIS_RTA_KAFKA_PORT`) |
| Қосымша Metabase, 1-модуль | `doris-rta-metabase` контейнері, `doris-rta-metabase-data` томы | 13000 (`DORIS_RTA_METABASE_PORT`) |
| 9-модуль кластері | `doris-rta-m09` Compose жобасы: үш FE, үш BE және HAProxy | FE сұрауы 19130, 19131, 19132 (`DORIS_RTA_M09_FE1_QUERY_PORT`, `DORIS_RTA_M09_FE2_QUERY_PORT`, `DORIS_RTA_M09_FE3_QUERY_PORT`), FE HTTP 18130, 18131, 18132 (`DORIS_RTA_M09_FE1_HTTP_PORT`, `DORIS_RTA_M09_FE2_HTTP_PORT`, `DORIS_RTA_M09_FE3_HTTP_PORT`), BE HTTP 18140 (`DORIS_RTA_M09_BE_HTTP_PORT`), HAProxy 19230 (`DORIS_RTA_M09_PROXY_PORT`) және статистика беті 18230 (`DORIS_RTA_M09_PROXY_STATS_PORT`) |

Мысалы: `DORIS_RTA_QUERY_PORT=29030 DORIS_RTA_HTTP_PORT=28030 DORIS_RTA_BE_HTTP_PORT=28040 .venv/bin/jupyter lab`.
Сынақ ортасының ішінде FE әлі де әдепкі 9030 және 8030 порттарын тыңдайды, ал хост порттары оларға бағытталады. BE веб-сервері де контейнердің ішінде өз хост портын тыңдайды, себебі FE Stream Load сұрауларын BE тіркеген мекенжайға қайта бағыттайды; ол мекенжай компьютеріңізден де жұмыс істеуі керек.

Сынақ ортасы бір FE, бір BE және бір репликасы бар, сақтау мен есептеуі біріктірілген бір түйінді Doris оқу ортасы; ол өндірістік кластер емес. Контейнер тоқтағанда атаулы томдар FE метадеректері мен BE деректерін сақтайды. 9-зертханалық жұмыс бөлек 9-модуль кластерін іске қосады, ол үшін алдымен сынақ ортасын тоқтату керек (`docker stop doris-rta`); 10-зертханалық жұмыс алдында 9-модуль кластерін қайта тоқтату керек.

Командаларды репозиторийдің толық көшірмесіндегі курс каталогында орындаңыз: тәуелділіктер курстарға ортақ ноутбук орындау ортасы `doris_labkit` пакетін `../../common` каталогынан да орнатады.    .venv/bin/python -m pip install -r requirements.txt

   ```bash
   .venv/bin/jupyter lab
   ```

3. [1-модуль: Apache Doris жүйесіне кіріспе](level1/module01-introduction/course.md) сабағын және оның `level1/module01-introduction/lab01_start_doris_and_build_baseline.ipynb` зертханалық жұмысын ашыңыз. **Зертханалық жұмысты бастапқы баптау** бөлімін, кейін ұяшықтарды ретімен орындаңыз. 2-бөлім сынақ ортасын іске қосады; алғашқы іске қосу Doris бейнесін жүктейді және бірнеше минут алады. Кейінгі зертханалық жұмыстар сол ортаны қайта пайдаланып, тоқтап тұрса, іске қосады.

- Ұяшықтарды ретімен орындаңыз. Қадамнан кейінгі **Күтілетін нәтиже** не көру керегін және оны қалай түсінуге болатынын айтады. Жасыл карточка тексерудің өткенін білдіреді; қызыл карточка жұмысты тоқтатып, айырмашылықты көрсетеді. Нәтижеңіз өзгеше болса, ештеңені өзгертпес бұрын мәліметтер мен ұяшықтарды орындау ретін қараңыз.

## Деректер жиыны

Зертханалық жұмыстарда Michael Kechinov жариялаған және [REES46 Marketing Platform](https://rees46.com/en/datasets) ұсынған [eCommerce behavior data from multi category store](https://www.kaggle.com/datasets/mkechinov/ecommerce-behavior-data-from-multi-category-store/data) жиынының түрлендірілген көшірмесі қолданылады. Курс көшірмесі `event_time`, `event_type`, `product_id` және `user_id` өрістерін сақтайды, тұрақты `event_id` қосады, әр пайдаланушыға сегіз жасанды `region` мәнінің бірін тағайындайды және бағаны тек сатып алулар үшін `revenue` ретінде сақтайды. 1-модуль түрлендіру мен авторлық деректерді толық сипаттайды.

| | |
| --- | --- |
| Жолдар | 2019-12-01 00:00:12 уақытынан 2020-03-11 04:53:08 уақытына дейінгі 10,158,080 оқиға (2019 жылғы желтоқсан мен 2020 жылғы наурыздағы 26 күн) |
| Файлдар | Ашық `doris-public-dataset` bucket ішіндегі шамамен 72 MiB болатын 40 Parquet файлы (AWS `us-east-1`): `s3://doris-public-dataset/doris-course/events/v1/events-*.parquet` |
| 3-зертханалық жұмыс үлгілері | `https://doris-public-dataset.s3.us-east-1.amazonaws.com/doris-course/lab3/v2/` мекенжайындағы үш шағын файл (жалпы шамамен 250 KB), `level1/module03-loading-data/downloads/` каталогына жүктеледі |
| Қолжеткізу | Ашық және тек оқуға арналған. Doris bucket деректерін S3 TVF және `"s3.credentials_provider_type" = "ANONYMOUS"` арқылы оқиды; AWS тіркелгісі не кілті қажет емес. |

Bucket түбірін қоса алғанда, барлық префикстерді анонимді тізімдеуге болады, сондықтан `events-*.parquet` үлгісі тіркелгі деректерінсіз жұмыс істейді. Bucket-ке файл жүктеу, бар файлдың үстінен жазу және файлды жою үшін рұқсаты бар AWS пайдаланушысы немесе рөлі қажет.

`datasets/events.yaml` дәл сол орналасуларды, схеманы, күтілетін жол саны мен уақыт аралығын тіркейді.

1-модуль деректердің құрылымын сипаттайды: 2019 жылғы желтоқсан мен 2020 жылғы наурыздағы 26 күн, әртүрлі күндерді қамтитын оқиға түрлері (сатып алулар тек жеті күнде) және сегіз жасанды аймақ.

<a id="clean-up"></a>

## Тазалау

Үзіліс жасау үшін сынақ ортасын тоқтатып, деректерін сақтаңыз; келесі зертханалық жұмыс оны қайта іске қосады немесе `docker start doris-rta` орындаңыз:

```bash
docker stop doris-rta
```

Курс каталогынан Kafka брокерін, қосымша Metabase контейнерін және 9-модуль кластерін де осылай тоқтатыңыз:

```bash
docker compose --file level1/module03-loading-data/compose.kafka.yml stop
docker stop doris-rta-metabase
docker compose --file level3/module09-sharding-replication/compose.multinode.yml stop
```

Курс жасағанның бәрін жою үшін курс каталогында мына командаларды орындаңыз. Олар курс деректерін жояды:

```bash
docker compose --file level3/module09-sharding-replication/compose.multinode.yml down --volumes
docker compose --file level1/module03-loading-data/compose.kafka.yml down --volumes
docker rm -f doris-rta doris-rta-metabase
docker volume rm doris-rta-fe-meta doris-rta-be-storage doris-rta-metabase-data
docker network rm doris-rta
```

Сіз ешқашан жасамаған нысанды, мысалы қосымша Metabase контейнерін атайтын команда оның жоқ екенін хабарлайды; қалғандары орындала береді. Содан кейін `docker ps -a --filter name=doris-rta` және `docker volume ls --filter name=doris-rta` ештеңе көрсетпейді. Қаласаңыз, курс жүктеген бейнелерді `docker image rm` арқылы жойып, `.venv/` каталогын, 3-зертханалық жұмыс `level1/module03-loading-data/downloads/` каталогына жүктеген файлдарды және `level1/module01-introduction/assets/` ішіндегі Metabase драйверін де жойыңыз.
