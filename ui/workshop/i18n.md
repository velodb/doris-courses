# Workshop language context

Learners choose a language after entering a workshop. The selector contains only
languages supplied by the installation. Existing v1 installations supply English.
Registering `kk-Cyrl` in the language registry does not install its messages or
course content. Runtime v2 installs the admitted package and projects its message
snapshot into each activity’s gateway and shared entry configuration. V1
activities retain English even when another activity installs both languages.

Language applies to the workshop's own entry, workspace, reader, progress forms,
Quiz controls and connection banner. JupyterLab, Doris FE, BI, Flink, Grafana and
Cognito hosted sign-in pages have their own language settings. Selecting a
workshop language does not establish language support in those applications.

## Messages and parameters

[ui.en.json](../../locales/ui.en.json) is the canonical English source. The
original 91 keys remain; the corpus now contains 231 messages. State metadata in
[src/copy.json](src/copy.json) refers to message keys. Templates contain escaped
message slots. The offline English design preview resolves the same state keys;
its sample navigation and settings remain review tooling and are not installed.

[ui.contract.json](../../locales/ui.contract.json) declares every key's exact
parameters. `text` accepts strings, `integer` accepts nonnegative integers and
rejects booleans, and `number` accepts finite numeric values. Simple named fields
are allowed; attribute access, conversions and format expressions are rejected.
`import.saved` defines `one` and `other` count forms for the registered English and
Kazakh UI. New languages must explicitly extend the count-form contract if their
rules need more forms. Parameters are checked before formatting. HTML consumers
escape the complete formatted string; message values never become markup.

The [consumer inventory](../../locales/ui.inventory.json) accounts for template,
renderer, portal, service, reconnect, progress and Quiz messages, including 22
static progress diagnostics. Unknown exceptions use a generic translated error;
paths, tokens and database diagnostics are not interpolated into learner copy.
Machine exceptions, access-denial API bodies, logs and third-party application
responses retain their existing meaning. A missing Quiz dependency is reported
in canonical English because no Quiz language context exists yet.

```bash
python tools/check_ui_messages.py
```

After adding a message, add its parameter contract, wire its consumer, regenerate
the inventory with `--write`, and reconcile the producer's stable source map.
Do not rename existing keys or recreate unit IDs. The producer freezes the
parameter contract and validates source and translated UI dictionaries.

## Selection and preference storage

Selection order is explicit `?locale=` URL, activity/learner preference, the
browser's installed-language match, then the installed default. Registry aliases
normalize to a canonical tag. Browser language ranges also allow region
truncation. Unknown or uninstalled explicit tags receive an unavailable response;
there is no silent English lesson under a target-language URL.

The external `locale.js` script pins every rendered tab's URL. Links and form
actions carry that locale. The selector changes only the current URL and its
preference; it preserves module paths, other query parameters and the current
fragment. Existing tabs keep their explicit choice. Switching language performs
no download of a language, Lab execution, progress write or deployment operation.

Preferences are browser-local `localStorage` values under
`doris.workshop.locale.v1.<sha256>`. The hash covers the trusted origin namespace,
activity and learner identity supplied by the server. Entry identity comes from
the signed assignment; reader identity comes from its installation and assigned
instance origin. URL parameters never supply identity. People sharing one
workshop account share its learner preference. Storage survives sign-out,
browser-session and server restarts on the same browser profile. Each origin has
its own preference storage; explicit links carry the selection between the entry
and assigned Jupyter origin. No cross-origin storage or authentication cookie is
introduced. Clearing browser data resets the preference.

There is no earlier language preference to migrate. Unrecognized stored values
are ignored; removed languages disappear from browser matching. An already open
URL naming a removed language shows unavailable. If storage is blocked, URL
selection remains usable; saving failures are shown when session storage permits.
With JavaScript disabled the GET selector and explicit links still work, while
browser-local preference restoration is unavailable.

## Consumer interfaces

[i18n.py](i18n.py) defines an immutable `LocaleContext` per request. The renderer
receives it through `Renderer(context=..., current_url=...)`. Portal and gateway
applications and the reader's `register` accept `installed_ui=InstalledUI(...)`.
An installation adapter supplies complete admitted message dictionaries, the
default locale and these callbacks:

- `content(path, kind, locale) -> (resolved_path, actual_locale)` selects a lesson,
  asset, Quiz or Notebook copy inside the installation's existing path allowlist.
  The reader explicitly redirects English navigation mirrors to `locale=en`.
  The adapter must preserve stable module/section anchors and verify package paths
  and hashes. Selecting a language does not create a Notebook copy.
- `anchors(path, locale)` supplies the same ordered stable IDs for body headings
  in each presentation, after the page title is removed. The renderer verifies
  count and uniqueness. Translated headings keep these IDs instead of generating
  a new slug from translated words. Target lessons without stable anchors report
  unavailable; historical English lessons keep their existing slugs.
- `labels(kind, identity, values, locale)` supplies the same display-field set for
  course/module/optional metadata. Structural identities are not translated.
- `LocaleContext.url(url)` carries the canonical locale to Quiz, Notebook and
  progress routes. It preserves other query values and fragments.
- `CourseQuiz.from_yaml(path, presentation=admitted, messages=context.messages)`
  binds question text and controls to one admitted locale. Use
  `switch_presentation(admitted, messages=..., source_path=...)` for equivalent
  language changes; `show()` starts a new attempt. Legacy English calls remain
  valid. The [Quiz/progress contract](../../doris-course/common/quiz-progress-v2.md)
  specifies stable IDs, frozen submissions, grading and migration.

Without the content adapters, a target-language reader explicitly reports
unavailable. The UI does not read or publish a private teaching tree. The [v2 package installer and Notebook-copy adapter](../../workshop/aws/runtime/multilingual.md) supply admitted content; shared Quiz/progress
presentation switching and migration use the session contract above. The
interfaces are verified using synthetic fixtures. They supply no real Kazakh translation or
native-language review.

UI upload uses bounded, independently receipted chunks and verifies the complete
archive hash before installation. Gateway message resources share its existing
asset stage. The SSM payload limit and unknown-dispatch handling stay enforced.

The UI archive and gateway overlay copy the canonical message engine and JSON
inputs at packaging time. The common helper wheel includes the same two JSON
resources via its package-data mapping. There is no second maintained dictionary.
The recovery script receives only the selected message subset through its
existing authenticated script endpoint, before JupyterLab captures `fetch`.

## Local verification

```bash
python -m unittest discover -s tools/tests -p 'test_workshop_i18n.py' -v
PLAYWRIGHT_MODULE="$PWD/ui/workshop/node_modules/playwright" \
  python tools/tests/run_i18n_browser.py --output /tmp/workshop-locale-review
```

The browser fixture uses real local portal, reader and gateway handlers with
synthetic dictionaries, test-signed identities and disposable Jupyter processes.
It checks two learners, concurrent tabs, preference restoration after a complete
restart, section preservation, images, unavailable languages, progress forms,
connection states and 1440/390/320 widths. Its Cyrillic strings are deliberately
synthetic. No cloud, database service, Docker or course Lab is started.
