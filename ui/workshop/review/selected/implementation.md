# 独立 UI 的实现交接

当前进展：用户在精简A版后要求继续，设计已收口。下列为原接入交接；自有门户、课程handler和安装包已按独立UI结构完成本地接入，详见 [当前架构](../../architecture.md)。没有云端部署。

## 目录职责

| 目录 | 负责 | 不负责 |
| --- | --- | --- |
| `ui/workshop/src` | 页面结构、视觉token、交互预览、英文UI文案 | 身份验证、服务归属、云操作、课程源内容 |
| `ui/workshop/assets` | 官方logo、字体、许可证 | 云配置、口令或实例数据 |
| `ui/workshop/contracts` | 展示数据形状及版本 | 授权规则或资源生命周期 |
| `ui/workshop/scripts` | 读取公共课程生成UI预览、浏览器检查 | 创建或连接AWS资源 |
| `ui/workshop/review` | 方向确认、规范、截图及验收依据 | 运行期依赖 |
| `ui/workshop/dist` | 本地生成的完整预览和组件参考 | 另一个课程仓库、生产部署包 |
| 现有运行/管控目录 | 认证、路由、subject与资源归属、代理、生命周期 | 新UI样式/模板的主要维护位置 |
| `doris-course` | 课程Markdown、Notebook、配图、清单 | Workshop UI结构和状态文案 |

公开运行代码不能依赖本机 `plan-doc`。UI源也不从管控包导入AWS客户端、operator工具、state或凭证。设计预览的课程快照是忽略提交的生成文件；任何课程修改回到课程目录，重新构建预览。

## 建议接入顺序

1. 在 `ui/workshop/` 增加实际服务端页面模板和构建输出，将展示样式放到同源静态CSS；复用此目录的token与copy。不要把原型整段HTML/JS写回handler字符串。
2. 在现有门户/课程handler增加很薄的数据适配：验证请求身份、确定活动和assignment之后，构造展示模型并调用独立UI模板。既有路由和校验顺序保持。
3. 公共入口只交付active活动；本人页的服务从已验assignment取得。UI不能根据浏览器learner ID、query或返回URL推导服务地址。真实多FE服务按分配map动态显示，不要求所有活动一定有四个Doris页面。
4. 课程handler传入课程manifest和安全渲染的正文。保留现有路径白名单、Markdown HTML关闭、图片限制与相对链接重写；模板不要再次信任未经处理的HTML。
5. 外部服务链接使用精确目的地，独立打开加 `noopener`。原生JupyterLab/Doris无UI注入；返回入口通过已验证配置构造，不接受任意return URL。
6. 最后按已核对的实际Cognito版本，独立准备限定CSS/合规PNG标识。平台表单继续托管，MFA/改密/错误文案由平台处理；不默认升级认证版本。

其中自有页面适配、静态资源与打包已本地实施；Cognito托管页品牌化和真实云端验证尚未进行。

## CSP 和认证

门户现有 `default-src 'none'`；不能为复制原型而放开通配符、任意inline脚本或外部CDN。生产优先服务端渲染、自有同源CSS；如调整资源策略，需逐项列明并复验既有负向测试。原型只为离线演示内嵌脚本，不能拿它的CSP直接替换线上CSP。

入口退出仍是同Origin检查保护的POST，清理当前Host Cookie并经过既有Cognito logout。不要改为无保护GET，不声称其他服务会话同步撤销。公开异常文案保持通用，已验证本人服务的未就绪状态才展示本人ID。
